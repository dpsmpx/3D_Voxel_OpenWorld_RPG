## 2. Как всё проверялось

Добавлен `tools/hostcheck/run.sh` — сборка и проверки на обычном
Linux-хосте без NDK:

1. **Сверка `CMakeLists.txt` с диском** — список исходников должен
   совпадать файл в файл. Именно расхождение здесь (`spwaner.cpp`,
   `vk.descriptors.cpp`) было одним из блокеров.
2. **Компиляция** всех 94 единиц трансляции с настоящими `glm`,
   `EnTT` и `Vulkan-Headers`; заголовки Android и AAudio — заглушки
   в `tools/hostcheck/include` с сигнатурами из NDK.
3. **Линковка** `libnative-lib.so` с `-Wl,--no-undefined`: доказывает,
   что в коде не осталось неразрешённых символов.
4. **Компиляция шейдеров** через `glslc`.
5. **Сверка вершинных форматов**: таблицы `vk::VertexAttr` в C++
   против входов `layout(location=…) in` в GLSL.
6. **113 тестов логики**: шум, ландшафт, ECS, аллокаторы, планировщик,
   формат сохранений, жадное меширование, сутки, фазы боссов, ASTC.

Заглушки могут маскировать часть ошибок, но не создают ложных.

## 4. Дефекты рантайма — устранены

| № | Дефект | Решение |
|---|---|---|
| 1 | **Use-after-free в `ChunkManager`**: задачи держали сырой `Chunk*` после освобождения блокировки, главный поток удалял чанк | переход на `shared_ptr<Chunk>`, соседи — через `NeighborLease` |
| 2 | Гонка на вокселях и мешах | `shared_mutex` на воксели, `mutex` на меши, захват соседей в порядке адресов |
| 3 | **`parallelFor` виснет навсегда**: счётчик увеличивался дважды | убран лишний `add` |
| 4 | `mem::Arena` падала на первом же выделении | переписана |
| 5 | `mem::Pool` инвалидировал указатели и разрушал объекты дважды | переписан на чанки со стабильными адресами |
| 6 | Время от эпохи: `float` давал шаг 128 с, ломая цикл суток | отсчёт от старта приложения |
| 7 | Ближняя плоскость frustum по формуле OpenGL при глубине Vulkan `[0,1]` | исправлена |

**Найдено сверх аудита:**

- **Вершинные форматы были зашиты одним вариантом** и совпадали только
  с воксельным шейдером. UI, контур блока, мобы, снаряды, NPC,
  предметы и трава рисовались бы мусором. Каждый рендерер теперь
  объявляет свой формат, совпадение проверяется автоматически.
- `dialogue.cpp` передавал `*(ChunkManager*)nullptr` в генератор
  квестов — падение при первом разговоре с квестодателем.
- `vk_context` выбирал семейство очередей графики, не проверяя
  поддержку презентации.
- Трава спавнилась по несуществующему `surfaceBlock()`.

## 5. Производительность

Замеры на x86-хосте, 16 чанков, `-O2`. На Snapdragon 660 цифры будут
в несколько раз выше — **проверка на целевом железе не проводилась**.

| Что | Было | Стало |
|---|---|---|
| Генерация чанка | 14,4 мс | **5,5 мс** |
| Меширование LOD0 | 5,1 мс | **6,1 мс** |
| Итого на чанк | 19,5 мс | **11,6 мс** |

Что изменено:

- **Маска greedy-meshing** была фиксированной 256×256 и обнулялась
  целиком на каждый из 384 слоёв: ~73 МБ `memset` за вызов, а вызовов
  было четыре (по одному на LOD) — около 295 МБ на чанк.
- **Климат и высота** пересчитывались по 3–4 раза на колонку.
- **Пещеры** проверялись выборкой шума на каждый воксель (~200 тыс. на
  чанк) — переведены на решётку 4×4×4 с трилинейной интерполяцией.
- **Загрузка на GPU**: `submitOneShot` с ожиданием fence вызывался по
  два раза на каждый из четырёх LOD каждого чанка — восемь полных
  остановок GPU на чанк. Теперь один пакет на кадр.
- **LOD грузится по требованию**, а не все четыре сразу.

### Осознанные отклонения

| Пункт | Состояние | Почему |
|---|---|---|
| **3.2 Многопоточная запись команд** | ❌ | Команды пишутся в одном потоке. Загрузка на GPU распараллелена (пакет на кадр), меширование и генерация — на воркерах. При ~250 draw call за кадр узкое место не здесь; вторичные командные буферы имеет смысл вводить, когда профилирование на устройстве покажет, что запись команд действительно упирается |
| **3.2 Deferred или Forward+ с кластеризацией** | ❌ | В сцене один направленный источник (солнце) и туман. Кластеризация источников света решает задачу, которой в игре нет; текущий forward-проход для такой сцены оптимален. Если появятся точечные источники (факелы, магия), решение придётся пересмотреть |
| **3.4 Чанки 32×32×32** | ⚠️ | Используются колонны 32×128×32. Для мира высотой 128 это тот же объём данных, но без вертикальной фрагментации HashMap и без склейки граней между вертикальными соседями |
| **3.4 Массив метаданных вокселей** | ❌ | Вместо него массив света. Механик, требующих поворота и состояния блока, в игре пока нет |
| **6 Сетка инвентаря 6×4** | ⚠️ | 27 основных + 9 быстрых слотов вместо 24 |
| **7 Формат OGG** | ❌ | Все звуки генерируются процедурно, декодер не нужен. Подключение `stb_vorbis` осмысленно вместе с реальными звуковыми ассетами |
| **9 Doxygen для *всех* публичных функций** | ⚠️ | Модульный API покрыт полностью. Тривиальные однострочные аксессоры не документированы намеренно: комментарий «возвращает x» к `f32 x() const` — шум |
